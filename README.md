# Check764P

Локальное Windows-приложение для проверки клиентов по XML сообщений Банка России и ведения накопленного перечня 764-П. Обрабатывает оригинальный профиль `СообщОтказ_115ФЗ` без namespace, версии 1.1 и 1.2, разделы 1.1, 1.2 и 2.

**Windows EXE собран и прошёл автоматическую проверку в GitHub Actions. Это кандидат для приёмки с документированными ограничениями; ручная проверка Windows 10/11 и проверка всех условий текстового формата ещё не завершены. Подробности — в [docs/STATUS.md](docs/STATUS.md).**

## Использование Windows EXE

1. На GitHub откройте **Actions → Windows validation and EXE → успешный запуск → Artifacts → Check764P-Windows-x64**. Если успешного запуска нет, готового проверенного артефакта нет.
2. Распакуйте артефакт. Скопируйте `Check764P.exe` в отдельную папку с правом записи, например `Документы\Проверка 764-П`. Установка Python, Microsoft Excel и доступ к интернету при работе не нужны.
3. Положите рядом книгу клиентов `.xlsx` и уже расшифрованные `CB_ES550P_ГГГГММДД_nnn.xml`. Имена XML сохраняйте исходными. Закройте открытые рабочие книги Excel.
4. Запустите EXE. При первом запуске выберите книгу, лист, строку заголовков (по умолчанию третью) и одну или несколько колонок ФИО/названий. ID, ИНН и дата рождения не обязательны; их колонки можно сопоставить дополнительно. Книга клиентов не изменяется.
5. Выберите первоначальное накопление из XML (покрытие «Частичное») либо импорт книги Check764P вместе с её `archive/xml`. Импорт таблицы только из ФИО/ИНН не считается полноценной базой для обновлений.
6. Дождитесь окончания. Кнопка **Открыть папку отчётов** открывает результаты текущего запуска. Кнопка **Настройки и повторная проверка** позволяет изменить сопоставление колонок и проверить актуальную книгу снова.

Рабочая папка определяется по расположению EXE, в том числе при запуске ярлыком. В ней создаются:

| Путь | Назначение |
|---|---|
| `Перечень 764-П.xlsx` | Основное накопленное состояние, история, сведения об обработанных XML |
| `Результаты проверки/<run_id>/01_*.xlsx` | Проверка клиентов по последнему XML, пакету и проекту действующего состояния |
| `Результаты проверки/<run_id>/02_*.xlsx` | Фактический итог обновления и его журнал |
| `archive/xml` | Исходные XML по SHA-256; автоматически не удаляются |
| `backups` | Предыдущие версии книги с run_id |
| `service` | Настройки, блокировка, журналы запусков и восстановления |

Совпадение текста — кандидат для ручной проверки, а не установление тождества лиц и не решение об отказе. Роль участника чужой операции показывается отдельно. При частичном покрытии отсутствие совпадений не подтверждает полноту перечня. Файлы `.enc`, `.sig` и уведомления другого профиля не используются как перечни. Расшифрование, проверка подписи и уведомление ЦБ выполняются пользователем отдельно.

Нечёткий поиск включён по умолчанию. Его можно отключить в настройках для больших наборов; отчёт явно укажет это ограничение. Поиск не ограничивает количество кандидатов. Частые слова и широкие критерии могут дать очень большой отчёт.

## Восстановление и перенос

Переносите всю папку целиком, включая master-книгу, `archive`, `service` и `backups`.
После аварии запустите программу повторно: она проверит журнал транзакции. При уже заменённой базе завершится публикация подготовленных отчётов. Если подготовленный отчёт утрачен, программа восстановит проверенную предыдущую базу, сохранив журнал. При неизвестном внешнем изменении книги обработка остановится.

Если мастер-книга повреждена, программа не создаёт вместо неё пустую. Сохраните копию всей рабочей папки. Восстановите нужную книгу из `backups` под именем `Перечень 764-П.xlsx`; исходные XML для повторного применения берите из архива и возвращайте их первоначальные имена по листу `ОбработанныеФайлы`. Применяйте полный пакет последовательно. При ошибке очередности не редактируйте историю и не удаляйте записи обработанных файлов вручную.

Книга содержит видимые листы `АктивныеЗаписи`, `Участники`, `ДействующиеЛица`, `История`, `ОбработанныеФайлы`, `Метаданные` и `Данные`. Последний хранит полные машинно-читаемые снимки, разбитые на части без потери длинных значений. В версии структуры 2 JSON сжимается zlib и кодируется base64 с префиксом `Z:`; версия структуры 1 также читается. Это часть XLSX, внешняя база данных не требуется. Контрольные суммы защищают от случайного редактирования. Изменять master-книгу вручную не следует.

## Разработка и воспроизводимая сборка

Требуется Python 3.12. Для сборки Windows EXE используйте именно Windows x64:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements-build.txt
python -m unittest discover -s tests -v
./scripts/build_windows.ps1
./dist/Check764P.exe --self-test --gui-smoke
```

PyInstaller собирает один файл с параметрами `--onefile --windowed`, включает оригинальные XSD и зависимости. SHA-256 схем проверяются до сборки и при работе. Runtime не устанавливает пакеты, не скачивает компоненты и не использует API/телеметрию. Распаковка библиотек PyInstaller во временный каталог — штатная часть запуска onefile; пользовательские данные туда не пишутся.

Workflow `windows-latest` выполняет модульные тесты, сборку и запуск самопроверки EXE, включая создание окна Tk. Артефакт публикуется только при успешном результате и включает EXE, SHA-256, сведения о среде самопроверки и точные версии библиотек сборки. `windows-latest` не заменяет отдельную ручную приёмку на Windows 10 и Windows 11.

Для запуска исходников: `python -m check764p.app`. На Linux используйте `.venv/bin/python` и графическую сессию для окна. В подготовленной облачной среде: `/workspace/.venvs/764p-proveryalka/bin/python`.

`examples/clients.xlsx` содержит исключительно синтетические имена. Все автоматические тесты создают синтетические XML. Самопроверка EXE: `Check764P.exe --self-test`; результат — `self-test-result.json` рядом с EXE. Она не использует рабочую базу клиента.

Нагрузочный тест: `python scripts/benchmark.py --records 100000 --clients 20000`. Результат сохраняется в `docs/validation/benchmark.json`. Это полный синтетический запуск с тремя участниками на запись, без нечёткого поиска; результат конкретного измерения и ограничения проверяйте в статусе приёмки.
